Plan: adopt the Anthropic browser toolset in Sasha

Branch explore-alternatives, on top of commit 4cf2ada. Written 2026-09-18, revised the same day after the decision to go Anthropic-only. Every claim is marked Fact (cited to a file, a command result, or the official docs) or Assumption (with what would confirm it).

Status. Implemented in the working tree (not committed). OpenAI and gateway paths are removed entirely; there is no provider switch. What is done and what is still open is in section 10.

1. Decision

Replace Sasha's hand-written browser tools (TOOL_SPECS in the old brain.py) with Anthropic's browser_toolset_20260801. Keep Chromium and Playwright as the hands. Anthropic only: the OpenAI and gateway providers, the llm/ package and the custom browser tools are deleted, not kept behind a flag. Rollback is git checkout master.

Fact The toolset is client-executed: "Your application runs every call against its own browser automation; nothing runs on Anthropic's side." (Browser use tool docs). So browser.py survives as the executor; what changes is the tool contract the model sees.

Fact The installed SDK already has the types: anthropic 1.6.0 in ../sasha-browser-poc/.venv ships anthropic/types/browser_toolset_20260801_param.py, browser_toolset_configs_param.py, browser_state_block_param.py, and tool_result_block_param.py has a toolset_name field (checked with grep). No SDK upgrade needed. No beta header needed; plain client.messages.create().

2.2 Members we get that we did not have

  • read_page with filter: "interactive", depth, and ref scoping. Capped at 50,000 chars by the contract.
  • find: natural-language query, up to 20 matches in ref format. We implement it; see section 5.3.
  • zoom: crop of a region, for reading small numbers.
  • hover, double_click, triple_click, right_click, scroll_to, wait.
  • Tabs: new_tab, list_tabs, switch_tab, close_tab. Replaces "always show the newest tab" (browser.py:42-45) with explicit tab ids.
  • Batch actions: several member calls per model turn, run in order, stop at first failure.

file_upload, read_console, read_network, javascript_exec stay disabled (the default). Also disable left_mouse_down, left_mouse_up, hold_key, left_click_drag, middle_click: nothing in workplace.md needs them and a smaller schema is cheaper. Fact Disabling is "configs": {"member": {"enabled": false}} on the toolset entry; unknown keys are rejected (SDK docstring in browser_toolset_configs_param.py).

  • The "push tree + screenshot after every action" pair at brain.py:184-185.

5.2 Phase 1: the executor, toolset_executor.py (done, tested offline)

One class, ToolsetExecutor(browser), with one small method per member and a thin dispatcher. Same style as _execute today: a match that only routes.

Ref registry. Per tab: a counter and a dict ref_id → element handle. Rules from the contract: never renumber within a tab until it navigates; on navigation, clear the tab's registry; a ref that no longer resolves returns the stale-ref error text.

Built on option 1 below. The spike passed: Accessibility.getFullAXTree, DOM.resolveNode and Runtime.callFunctionOn work on the bundled Chromium; element centres come from getBoundingClientRect in page JS rather than DOM.getBoxModel, so text-node refs (a tooltip name, a swatch label) resolve to their parent element.

  1. CDP accessibility tree (built). Open a CDP session on the page (context.new_cdp_session(page)) and call Accessibility.getFullAXTree. Each node has a role, a name, and a backendDOMNodeId. Map ref_N → backendDOMNodeId. To act: DOM.scrollIntoViewIfNeeded, then DOM.getBoxModel for the centre, then page.mouse.click; for form_input, DOM.resolveNode then Runtime.callFunctionOn to set the value and dispatch input/change. This gives the browser's own roles and names, the same ones aria_snapshot() prints today, so the model sees names that match what it already learned from workplace.md. Assumption Playwright's Python new_cdp_session and these four CDP methods behave as described on the Playwright-bundled Chromium. Confirm with a 20-line spike on the deal page before building on it.
  2. JS walker (fallback). Inject a script that visits visible elements, computes role and name in JS, stamps data-sasha-ref="ref_N" on each new element, and returns the lines. Acting is page.locator('[data-sasha-ref="ref_N"]'). Simpler to act on, but role and name computation in JS is a re-implementation of what the browser already does, and it is where the current unnamed-field problem came from.

read_page. Print one line per node: role "name" [ref_N], indented by depth, in document order. Include the current value for textboxes and comboboxes (value="…"), the checked state for checkboxes and radios, and disabled when set. For an input with an empty name, append the near-label from the existing heuristic at browser.py:185-201 as (near: "Proof Title"). Honour filter (interactive keeps links, buttons, textboxes, comboboxes, checkboxes, radios, options, tabs, menuitems), depth, and ref (subtree). Cap output at 50,000 chars. Refs are assigned on first sight and reused on later reads until navigation.

find. No model call. Tokenise the query, score every registered node by overlap with its role, name, near-label and placeholder, return the top 20 in read_page format. If nothing scores, say so in the text. Assumption Lexical matching is enough for a CRM whose labels are already written into workplace.md. Confirmed if the benchmark turns in section 6 pass; if not, the fallback is a small model call, which we would rather not add.

Actions. Each click member resolves its target (ref or coordinate) and calls Playwright, then browser._settle() and _dismiss_toasts() as today. Keep the parent-click fallback from click_text for tooltips and swatches. type is keyboard.type. key parses chords (ctrl+a → Control+a; on macOS map ctrl to Meta for select-all and copy/paste) and sequences (split on spaces) with repeat. scroll moves the mouse to the target then wheels scroll_amount × 120 px, matching browser.py:151-156. scroll_to is scrollIntoViewIfNeeded. wait is wait_for_timeout.

form_input. Resolve ref; for select, use Playwright select_option(label=…) then by value; for checkbox and radio, set checked from the boolean; for text inputs, textareas and contenteditable, set the value and dispatch events, then read it back and return Set '…' to 'value'. Now contains: '…', keeping the read-back that fixed the empty-note bug (README, "Why hybrid").

screenshot and zoom. page.screenshot() of the viewport as today; zoom uses Playwright's clip. Return an image block only. Assumption The 1440×900 viewport (browser.py:21) is under the image limits, including the stricter per-image limit once a request holds more than 20 images. Confirm at the vision size limits page before the first run; if not, add downscaling and coordinate rescale in the executor. Assumption Returning the zoom crop without upscaling is acceptable; the docs describe it as "cropped, upscaled". If the model struggles to read small numbers, add Pillow and upscale ×2.

Tabs and browser_state. Assign tab-N when a page opens (context.on("page")). Track the active tab explicitly instead of "newest wins". navigate, and any action after which the tab list or the active URL changed, appends a browser_state block with the full tab inventory and a tab_opened change when relevant. Tab members return only that block. Downloads are not expected; do not report them.

Navigation guard. Accept the three history keywords, add https:// if the scheme is missing, refuse anything not http/https, and refuse hosts outside ALLOWED_HOSTS, re-checked on the final URL after redirects.

Errors. Any exception inside a member becomes is_error: true with Error: <type>: <msg[:300]>, as brain.py:248-249 does today. Stale refs use the docs' exact wording.

Estimated size: 300 to 400 lines. Old Browser methods remain for the custom-tools path; the executor calls only browser.page, _settle, _dismiss_toasts, and the near-label JS, which should be lifted into a named helper so both paths share it.

5.3 Phase 2: the LLM layer, llm.py (done)

  • tools is [BROWSER_TOOLSET, REPLY_TOOL]: the toolset entry with the configs from section 2.3, and reply_to_client with an input_schema.
  • ToolCall carries toolset_name (read from block.toolset_name, present on ToolUseBlock in SDK 1.6.0).
  • The assistant turn is replayed as the raw response blocks, so thinking blocks go back unchanged.
  • All tool_result blocks for a turn go back in one user message, in call order, each with toolset_name: "browser" for browser members and none for reply_to_client.
  • Cache breakpoint on the last message kept.

  • Batch rule: after the first browser failure, every later browser call in that turn gets the halt text and is_error. reply_to_client in the same turn after a failure: still honour it (the model may be reporting the failure to the client); Assumption this reading is right. Confirm by reading how often it happens in run.json after the first week.
  • Nothing is pushed after an action. (The optional "attach a tree to the last result of a batch" idea is not built; add it only if the measured round-trip count says so.)

6. Risks

  • Refs on a single-page app. The CRM re-renders often. If a node is replaced by React, its ref goes stale even though the page looks the same. The contract says return the stale error and let the model re-read. Assumption This costs one extra round trip now and then, not a failure. Confirmed or broken by the stale-ref count in section 5.6.
  • find quality. Lexical only. See 5.2.
  • Provider lock. Anthropic only (Claude API or Vertex). The team's gateway cannot serve this code. Accepted by decision on 2026-09-18.
  • Behaviour drift from on-demand observation. The model may act without looking. The playbook's "after any write, look again and confirm it saved" (playbook.md:12) is the guard; the verification turns test it.
  • Cost surprise in the other direction. Fewer images per turn, but batch actions may produce more calls per turn and more read_page text. Net token effect is unknown until measured.
  • Prompt injection classifiers are on by default and may pause the model to ask whether an instruction came from us. On an internal CRM this should be rare. Leave on.

7. Out of scope

  • Scripted flows for the quoter and stock checker (the alternative discussed earlier). Separate decision; can be layered on later as extra custom tools next to the toolset.
  • Sending the reply anywhere. Still returned as text.
  • Concurrency in api.py. Still one browser, one request.
  • Migrating the OpenAI or gateway path.
