Plan: three kinds of knowledge

Branch explore-alternatives. Written 2026-09-18, after three live turns on the Anthropic browser toolset (303688 twice, 303837 once). Claims are marked Fact (cited to a file, a run, or a command) or Assumption (with what would confirm it).

1. The goal, and why the current loop never ends

Goal. Sasha does what the client asked, using the browser and the rulebook. Not: every control on every page described in a prompt.

Why the loop never ends today. Fact In the 303837 turn (runs/deal_303837/turn_20260918_144156/run.json), 28 model rounds, 82 browser calls, 0 errors, correct answer. About 13 rounds were wasted on: the colour box swallowing the first keystrokes (4 times), style-code typos (1717, 64000 twice, 3001), and find not seeing react-select inputs. Every wasted round was a widget-mechanics problem. None was a judgment or rulebook problem.

Fact The lines added to prompts/workplace.md today were also widget mechanics: the qty box is a spinbutton (line 28), swatches are tooltip-only so click by coordinate (line 65), radios have no name so click by coordinate (line 106). The map has been absorbing executor gaps. Each new page with the same widget produces another line. That is the loop.

The test for a line. If it names a page, what is on it, or a rule the CRM enforces, it belongs in workplace.md. If it says how to operate a control ("type, then click the option", "click by coordinate", "shows as textbox "e.g. 12""), it is an executor gap. Fix the executor and delete the line.

6.2 The harness

evals/asks.json holds the table. evals/run.py runs each ask with --reset, then applies the checks it can automate and prints a table for a human to grade the rest:

  • Automatic from run.json: rounds, calls, images, stale refs, halts, cost estimate; which URLs were visited (stock checker this turn, quoter this turn); whether any call hit a Save, Submit or Order control (from the tool result text and tree lines); reply regex (contains a dollar amount, contains "one size", signs off correctly).
  • Automatic from the CRM after the turn (read-only, using the executor): proof count on the deal, qty on the proof, presence of a Revision N chip. Compared with a snapshot taken before the turn.
  • Human: is the price in the reply the one the quoter showed; is the tone right. One column, yes or no.

Score = asks fully passing. Also report rounds per ask, because a pass at 28 rounds is not the same as a pass at 8.

6.3 The stop rule

Done for this phase when: all 10 pass, twice on separate days, with the widget lines from section 3 deleted from workplace.md, and no ask over 15 rounds. Then new asks are added only when the client does something new, not when a widget misbehaves.

7. Order of work

  1. Baseline. Write evals/asks.json and evals/run.py. Run the ten asks as the code is now. Record the score and rounds. Nothing else changes in this step. Cost: (Assumption) about $1 per ask on Opus 5 at today's cache rate, so about $10 per full pass.
  2. Widget classes A, B, E. Combobox handling, keystroke check, action feedback. Rerun asks 2, 3, 4, 5. Expect rounds on ask 4 to drop below 15.
  3. Widget classes C, D, H. Hover feedback, right-side labels, find on comboboxes. Rerun asks 2, 4, 6.
  4. Strip the map. Delete the lines marked "Go" in section 3; move the two rule fragments and the "pick 2-3" line. Rerun all ten. Must not regress. If an ask regresses, the executor is missing a class, not the map a line.
  5. Playbook line on numbers. Rerun asks 3, 4, 6. Check the run.json shows get_page_text before each price in the reply.
  6. Freeze. Put the section 2 test in the header of workplace.md. Second full pass on another day. Update the README results table.

9. Not in this plan

  • Deterministic tools for quoting and stock (code instead of browser for the hot flows). Only if the eval plateaus after step 4.
  • Sasha writing her own page notes. It is the same loop with a worse author, and wrong notes persist (the "confirmed stock" story in the README).
  • Model or effort changes. Same model throughout so the eval measures the code, not the model.

Assumptions (collected)

  • Widget classes A and B remove most of the wasted rounds on the quoter. Confirm: ask 4 under 15 rounds after step 2.
  • Tooltip text appears in the DOM on hover so class C can read it. Confirm with a probe on the stock checker swatches; if it does not, coordinates stay the fallback and the map line becomes a playbook-free executor note.
  • Ten asks are enough signal. Confirm by stable scores across two passes.
